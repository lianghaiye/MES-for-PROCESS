# 批令支线「本次启用」

## 业务背景与目标

工艺路线已有主线 / 支线 / 汇合点后，配方再配并行组 + any/all 门槛过高。改为：**结构以路线为准**；同批执行时现场可关掉本次不做的支线阶段。

## 核心业务流程

1. 配方挂工艺路线；下发批令时 `snapshotSteps` 按路线节点 `processId` 给阶段打 `pathKind` / `routeNodeId`，默认 `enabledOnOrder=true`。
2. 批令「工艺阶段」表：支线显示开关「本次启用」；主线 / 汇合 / 未匹配路线 → 不可关。
3. 关闭后：不可确认本步、从已确认列表剔除该步、完工不要求该步。
4. 开启「批次阶段时序确认」时：只卡仍启用的主线/汇合点先后；支线互不强制；**无 any/all**。

## 关键业务规则与约束

- 仅 `pathKind === branch` 可切换。
- 旧快照无 `pathKind` 时，`getBatchOrder` 按配方路线补打。
- **功能参数「支线处理方式」**：`same_batch` / `spawn_order` / `both`（默认 both）。选「仅另开指令」时不展示本次启用；选「仅同批关支线」时关掉下游开单入口。

## 数据模型与接口关联

| 字段                                            | 含义                    |
| ----------------------------------------------- | ----------------------- |
| `routeSnapshot[].pathKind`                      | main / branch / sink    |
| `routeSnapshot[].enabledOnOrder`                | 本单是否启用，默认 true |
| `setBatchStepEnabled(orderId, stepNo, enabled)` | 切换支线启用            |

## AI 与开发维护要点

- 工具：`src/utils/batchStageEnable.js`
- 时序：`enabledStepSequenceErrors`（替代配方并行组）
- 入口：`BatchInstructionDetailView` 工艺阶段表；配方编辑已去掉并行列
