## 产品主数据

**需求说明**

产品信息保留，作为配方、计划和库存的物料。流程型不再按件维护。

1. 计划策略改为两项：按批生产、备库存。只有备库存必填最低库存。原来的按单、备货、按单兼备货分别归入这两项。
2. 主单位用重量或体积（kg、L、m³）。检验项可以维护。不维护含量，含量只记在批次上。不单设密度。重量和体积要换算时，在辅助单位上填默认换算率。配方、入库、发货不使用密度。
3. 不按实测含量拆 SKU。98.6% 和 99.1% 不是两个产品。合格标准不同、工艺也不同的档次才分开建产品，例如工业级碳酸锂和电池级碳酸锂。
4. 启用效期默认否。启用后才维护保质期，批次写失效日期，投料和发货拦截过期批次。
5. 工时、下料、图号、材质改为可空，保存不拦截。
6. 供应型态四项：**自制**（本厂产线）、**外购**（直接采购）、**外协**（本厂有配方或规格，原料发出去外厂加工后再收回）、**客供**（客户来料，不产生采购）。外协不是工序外协，也不是离散的外协件拆工单。

## 配方管理

**需求说明**

产品 BOM 改为配方。菜单和详情都叫配方。状态仍是待发布、生效、归档，同一物料同时只有一个生效版本。

1. **当前表头**：配方类型（标准/试制/客户）、基准批量、理论得率、可选工艺路线、是否默认。主产品理论产出 = 基准批量 × 理论得率，并回写主产品产出行预期数量。  
   **未落地（二期）**：表头「整批 / 槽次」批量规则、槽次所在罐、主元素收率目标。
2. **投料行**：投料量与配比二选一；「按含量折算」是开关。开启后配方行填假定含量（界面 %，存储 0～1），**理论投料** =（投料量或基准批量×配比）×(1+损耗)÷含量；编辑页与详情均展示「理论投料」列。现场实投含量优先手填，否则取原料批次含量，**不以配方含量回落**；开了按含量折算且缺含量不能过账。  
   **未落地**：化验公式投料（系数 × 取样实测 × 体积）。
3. **产出行角色**：主产品、联产品、副产品、**回收料**、**废弃物**。物料从主数据选择；主产品有且只有一条，且必须是本配方所属物料。指定**产出工序**（对应配方工艺阶段）。  
   **去向不在配方维护**：过账时在批次指令选择（待判定 / 入仓库 / 入储罐 / 回用 / 再提 / 废弃）。  
   **未落地**：产出行「元素去向」（产品/渣/尾液/回流/不计入）。
4. **产出化验**：产出行只配 **产出化验**（勾选启用 + 门禁必选）。过程检（投料前核对 / 中控取样 / 转序放行）在工序化验方案上配置，不在产出行出现。选产出工序后，若该工序已带出成品检方案则勾选带出；可在本配方改门禁，不回写工序主数据。
5. 中间体做成独立物料、独立配方；下达时不自动拆下一层。同一步多条产出（如卤水与渣）写在同一配方产出表、可挂同一产出工序。
6. 去掉母件用量、下料尺寸、子件 BOM。历史树形 BOM 不迁移。
7. 投料行可指定所属工艺阶段。批次在该阶段投料时默认带出挂在该步的物料与理论量；未指定阶段的不默认带出，现场可补加。
8. **工艺阶段**：从工序配置选工序，带出参数与**过程化验方案**快照（可在配方侧随阶段保存）；阶段可维护设备分类与候选设备。执行快照以配方内嵌阶段为准（`routeSnapshot`），不以路线网格替代阶段顺序。

## 工艺路线与工序

**需求说明**

配方可挂一条工艺路线（设备候选、引用统计等）。**批次执行顺序与门禁以配方「工艺阶段」快照为准**，不是直接跑路线网格的每一步。

1. **工序配置（当前）**：编码、名称、分类、操作说明、允许设备、资源类型（一期仅岗位）、默认执行岗位、默认门禁、默认转移条件、**化验方案清单**（业务类型 + 化验类型 + 门禁）、可选过程记录模板。化验方案类型：过程化验下的投料前核对 / 中控取样 / 转序放行，以及产出化验（成品检，供产出工序带出）。门禁：记录（不挡确认）/ 硬门禁（确认本步前该方案最新结果须合格）。工序列表展示被引用数（按引用该工序的路线条数，同路线多次只算 1）。
2. **确认本步门禁（当前）**：只校验本步 **过程检** 硬门禁方案；产出化验不挡「确认本步」。批次「化验」弹窗为过程检**清单**（类型 / 门禁 / 状态 / 发起），不是单选目录。
3. **工艺参数（当前）**：配方阶段用自定义参数行（名称、单位、目标/上下限），不强制温度/时间/转速/pH 四键；额外采集项走工序过程记录模板。
4. **取样点模型**：当前用「化验方案」替代独立取样点表（无 dose/release 用途字段）。模板匹配按业务类型 + 化验类型 + 物料 + 工序。
5. **路线编辑器**：仍保留网格/并行与完成方式等离散能力；流程型执行不依赖「同一步多工序并行」。酸浸、水浸、火法等各做一张配方；汇合发生在下一张指令领用上游产出，不在路线上画汇合。
6. 去掉报工类型、计件单价、计薪口径、作业分项、下料、拆解、工序外协（主流程不用；种子里遗留 operations 字段不作为产品能力）。

   **为何默认执行只取岗位：** 现场按岗位领任务、换班交接；挂具体人交班后无人可领，挂班组无法落到岗位任务池。

## 产线管理

**需求说明**

一个工厂可有多条产线。产线是排产、执行、分发任务的产能单元，不是单纯的车间名称。

1. 产线主数据维护编码、名称、所属车间、状态、备注，以及**有序工段**。设备与岗位挂在工段上，不再在产线根级扁平多选。新增/编辑在**新标签页**打开（工段表 + 拓扑预览，不用弹窗）。
2. **工段有顺序**：按工艺顺序添加、上移/下移；主线工段序号连续。每个工段可选多台设备、多个岗位（1 工段 : N 设备/岗位，不要求设备与岗位一一对应）。
3. **产线可有分支**：工段路径分「主线 / 支线」。支线须指定支线名称、从哪个主线工段后分出、汇入哪个主线工段前（汇合可不填，视为线末）。列表展示拓扑摘要；编辑时展示主线 + 支线拓扑预览。
4. **生产计划必挂产线**。同一配方、同一期间，不同产线可各有一条计划；唯一性按「配方 + 期间 + 产线」。拆下级计划时继承上级产线。
5. **批次 / 槽次指令挂产线**：从计划开启时带出计划产线；列表与详情展示产线。后续现场任务按该线工段关联岗位分发，设备选用优先落在该线工段挂的设备上（硬约束可二期加强）。
6. 产线停用后不可再被新计划选用；已挂历史计划与批次保留展示。
7. 不做：把产线当成工艺路线的替代；路线仍描述怎么做，产线描述在哪套产能上做。不做产线内复杂并行网（多进多出图编辑）；一期仅主线 + 可标注的支线分出/汇合。
8. 设备称谓统一为「设备」（与设备台账一致）。产线工段、配方阶段选设备支持边搜边选与「选择更多」。
9. 配方工艺阶段：可先选**设备分类**，再**多选候选设备**；执行/开槽次以计划产线工段设备为准，配方候选为默认范围。
10. **投料计划不选工艺路线**：选配方 + 产线即可；路线挂在配方上，随配方带出阶段结构。

## 储罐与库位

**需求说明**

库位类型仍为货位、储罐、料仓。储罐和料仓增加罐容、单位、运行上限、库存方式。

1. 保住批次身份：罐内按批次分列。反应槽用这种方式，槽次没转出前占着这台罐。部分转移时拆出新批次，带上状态、含量和检测项。
2. 混罐：罐内不保留来源批次。母液罐、中转罐、汇流罐用混罐。领出时生成新批次，检测项按来源数量加权，只记录这一层直接来源。来源里有不合格则不能领出；有待检则领出批次为待检；否则有让步接收则为让步接收。
3. 结存不能超过罐容，超过的转入和产出直接拒绝。运行上限可空，建议约为罐容的三分之二。超过运行上限允许过账，并给出提示。
4. 罐间转移走调拨。源罐保住身份时要指定批次；源罐是混罐时按领出规则生成新批次。

## 生产计划

**需求说明**

生产计划不再拆零件工单，也不算齐套。新增时先选主产品，再在该产品已生效的配方里选择；一个产品可以有多张配方，有默认配方时先带出默认配方，仍可改选。不为联产品、副产品单独下计划。产出含量等化验完成后再写到批次上。

1. 整批配方：批次数等于需求量除以基准批量后向上取整。每一张都按完整基准批量下达，不生成尾数批。例如需求 100、基准批量 30，生成 4 张，每张按 30 计算。
2. 连续线不走这条拆法。按配方维护投料计划，期间为月、周、日，也可自定义起止日期，目标投料量由人填写，**必须选择产线**。计划编号可手填，未填按系统规则生成；计划名称默认为「期间 + 期间类型 + 计划」，可改。选了配方并填写目标投料量后，按配方理论得率算出理论产出（目标投料量 × 理论得率）。实投汇总该期间该产线槽次上主原料的实加量，不另记一笔账。下一级目标之和可以不等于上一级。当天没有产出，日计划不关闭。
3. **拆日与拆分规则（当前）**：新增计划选「拆成日计划」、或列表「拆分子计划」选拆到日时，展示「拆分规则」：
   - **跳过休息日**（默认勾选）：跳过周六、周日，目标投料量只均分到工作日；不勾则按自然日全拆。
   - **跳过法定假日**：界面占位，**置灰不可选**（未落地）。
     拆周不过滤。期间若勾选跳过休息日后没有工作日则拆分失败提示。  
     **未落地**：法定节假日过滤、工厂工作日历、调休补班。
4. 有原料才生产的线（如水浸）没有日目标就不排。系统不根据原料价格建议投多少。
5. 销售订单只生成成品的批次计划。库存低于最低库存时也生成批次计划，写入补货台账，不记零件缺口。库存下限不是连续线的唯一开工原因。
6. 计划按供应型态分流：自制生成批次指令；外协生成外协订单（可带发料参考量）；外购生成采购申请。连续线的日目标不自动拆成指令，槽次由现场另开并继承计划产线。不再生成总装、部装、加工工单。
7. 计划详情的过程指标中，联产品、副产品各占一张卡（回收料、废弃物不进这组卡）。先按配方产出明细画出联/副产品；尚未入库时数量为 0。本计划及下级批次已入库且配方明细没有的联/副产品再补卡。数量按已入库实收加总，同物料合并。

## 外协（流程型）

**需求说明**

保留外协订单、外协发料、外协收货、外协明细菜单，按流程型改规则。典型场景：火法整段外发——本厂配好料、发出原料和辅料，外厂加工后收回，本厂记转化率后再进水浸。

1. 外协订单挂供应商、收回物料（可关联生效配方）、约定含量或约定转化率。发料行按配方投料量带出参考量（重量/体积），现场按批次实发，实发可以和参考量不同，两者都留痕。
2. 外协发料按原料/辅料批次出库扣库存，必须挂在外协订单上。只能发合格或让步接收批次；启用效期时不能发过期批次。不做齐套、不按件数 BOM 发料。
3. 外协收货收回加工后物料，生成待检批次；记约定含量、实测浸出和转化率（实测 ÷ 约定）。一车一批时分开堆放。质检走外协回货检（规则同来料检：上下限 + 实测，可让步接收）。放行或让步接收后才能被后续投料选中。
4. 一张外协订单可多次发料、多次收货。明细能对照：已发原料量、已收回量、转化率。追溯能从收回批次看到对应外协单和发出批次。
5. 不做：工序外协（工单某一步外发）、装配齐套、按件外协工单。纯买回来的料仍走外购 + 采购收货，不走外协。

## 批次指令

**需求说明**

生产工单改为批次指令。一张指令一个批次号，数量是重量或体积，不是件数。状态为：**待下发**、**执行中**、**完成**、**已作废**。执行中包含等待化验和槽内补加，不另设状态。

### 列表

1. **筛选（点「查询」后生效）**：批次号关键词（同时匹配批次号 / 主产品名 / 配方名 / 来源标签）、状态、主产品、配方、来源、工作中心、创建时间区间。下拉选项来自现有指令数据。
2. **列**：序号、状态、批次号（点开详情）、工艺阶段、主产品、批序、计划投料量、实投、实际产出、得率差、配方、工作中心、来源计划、创建人/时间、最近操作人/操作时间、操作。支持列显隐持久化。
3. **批序**：仅 `batchCount > 1` 时显示 `seq/batchCount`，否则 `—`；连续线槽次不按离散「拆批」理解。
4. **工具栏**：生成批次指令；批量下发（仅待下发）；终止（待下发或执行中 → 作废）；已选计数 / 清空。
5. **行操作**：待下发 → 下发 / 指定下发 / 编辑 / 删除；执行中 → 完成；作废走批量「终止」或详情页。

### 下发与完成

1. **当前**：下发时按配方基准批量生成理论投料 / 预期产出快照；可挂产线（工作中心）。指令数量在下发时即确认（演示与主路径均为已确认数量）。  
   **未落地**：槽次数量/体积先空、执行中累加、完结前确认且卡罐容；数量未确认前理论量显示「待确认」。
2. 同一天、同一配方可以有多张执行中指令，可挂所属产线。前后段并行靠多张指令 + 罐/库衔接，不用一张指令串整条线。
3. 第一期在 Web 录入。确认本步记参数实绩与通用记录；投料 / 产出分弹窗过账。过程化验在「化验」清单按方案发起；产出化验只在「产出登记」勾选后生成。
4. **完成条件（当前）**：各步已确认、投料已记账、产出已过账（及允差等既有校验）。全部步骤确认但完成条件不齐时，详情页头展示警告条与 `completionBlockers(完成阻断原因)`。  
   **未落地**：主元素检测齐全且收率已算出。
5. 打印为批次标签（不打到袋/桶）。

### 详情页

1. **页头**：当前阶段、步骤进度（已确认/总步）、实投、实际产出、得率差；按状态展示编辑 / 删除 / 下发 / 指定下发 / 投料 / 产出登记（有待登产出时）/ 完成 / 作废 / 返回列表。
2. **Tab（固定顺序）**：基本信息｜投料明细｜取样检验与放行｜批记录（EBR）｜产出与追溯｜工艺路线｜操作日志。
3. **基本信息**：meta（创建时间 / 工作中心 / 来源计划）+ 主产品、配方、工艺路线、计划投料量、批序、理论产出、前批次（返工时）、**异常偏差**、备注；下方嵌「工艺阶段」执行表。
4. **投料明细**：按阶段卡片 + 物料卡；可筛阶段 / 物料名 / 编号；过账记录可展开；含量待补可补录。
5. **取样检验与放行**：过程检清单（非产出检）：工序、设备、取样位置、方案、类型、门禁、检单、状态、实测、结果等。
6. **批记录（EBR）**：步骤、项目、来源 Tag（系统 / 参数 / 投料 / 过程检 / 手工）、值、时间。
7. **产出与追溯**：顶部「异常偏差」区块 +「产出与物料平衡」+「产出与追溯」明细（见「联副产品与产出」）。
8. **工艺路线**：下发设备路线快照（列/行/工序/设备/回流/阶段进度等）；可「打开阶段」。
9. **操作日志**：时间、操作、人、说明。

### 工艺阶段表（基本信息内）

1. **列**：序、状态（已确认/未确认）、阶段、设备、岗位、配方要求、转序条件、化验（过程检堆叠摘要 + 硬门禁「硬」）、实绩摘要、产出（角色 Tag + 量 + 去向）、操作。
2. **设备**：本步绑定的执行设备（配方/路线快照）。
3. **配方要求**：本步工艺参数设定与上下限（只读）。
4. **工艺参数实绩**：确认本步时录入的实测值，写入 `paramActuals` / 批记录。
5. **化验列**：过程检清单摘要（类型 + 状态 + 是否硬门禁）；产出检提示走「产出」。
6. **实绩摘要**：有投料则 `投料 {合计}`；有参数实绩则全部列出；都有则分号拼接；已确认但无数值 → `已确认`；否则 `—`。
7. **行操作（执行中）**：有计划投料 →「投料」；有过程检方案 →「化验」；有计划产出 →「产出」；「确认本步」/「重新确认」（可按功能参数强制顺序确认；硬门禁未过、未投料、设备未选等可禁用）。

### 异常偏差（整单）

异常偏差是**整单说明**，不是每一笔产出过账的流水字段。

1. 字段：`deviation(最新说明)` + `deviationLogs[{ at, text, operator }](历史流水)`。
2. **写入时机**：仅在「产出登记」弹窗的「补充异常偏差」有填写内容、且确认过账成功时写入。
3. **规则**：留空 → **不覆盖、不追加**；有内容 → 追加一条流水，并把 `deviation` 更新为最新文案。若历史上只有 `deviation`、尚无流水，首次追加前把旧值迁入流水。
4. **展示**：基本信息全文；「产出与追溯」Tab 顶部「最新说明」；`deviationLogs.length > 1` 时出「历史 (N)」；历史弹窗为时间线倒序（时间 · 操作人 + 正文）。
5. 不做：每次过账强制必填；不做静默整单覆盖（旧逻辑已废弃）。

## 投料

**需求说明**

领料管理保留，作为投料前面的发料步骤：从仓库选定原料批次发出。投料明细单独成菜单；批次指令上「投料」弹窗当场指定扣减来源并过账，库存立即减少。原来的不领料、完工预扣、自主领料三种扣料方式停用。

### 可选批次与参考量

1. 只能选择合格或让步接收、且未过期的批次。待检、不合格不出现在可选列表。启用效期的物料按近效期先出。
2. 参考量（理论投料）按配方计算。整批相对基准批量；槽次在数量确认后按「下达数量 ÷ 基准批量」缩放。开了按含量折算的行，下达时用**配方行假定含量**除出理论投料；现场过账时记录实投含量（手填或批次含量），**不以配方假定含量回落**。  
   **未落地**：化验公式投料（系数 × 取样实测 × 体积）。
3. 实加量可以和参考量、指导量不同，两笔都留下。
4. 补加：勾选「补加」可带出其他阶段或未指定阶段的物料；同物料多次投料按轮次累加。需要加入配方以外的物料时，记计划外投料行为，计入实际消耗，不回写配方（**计划外投料独立字段未单独建模**）。
5. 不能按物料合计估数出库；必须落到批次或库位 FIFO 扣减，从而把含量带进成本与收率。

### 投料过账弹窗（当前）

1. **壳**：宽约 `min(1600px, 96vw)`；基本信息：阶段（必选）、补加；上一步中控取样只读提示（不拦截）。
2. **「本次」勾选**：默认全勾；表头可全选/取消；取消勾选后该行置灰不可填，确认时跳过（不必先清空实投量）。
3. **明细列**：本次、序号、原料、编号、规格、投料来源（再提整单锁定时不展示）、理论量、已投、原料批次、来源储罐/库位、实投量、有效含量(%)、**指导量**、化验单号、检验结论。
4. **投料来源**：`fresh(线边新料)` / `recycle(回流料)`；切换来源清空批 / 库位 / 含量 / 检单信息。再提指令整单为再提来源，只选手选批。
5. **扣减方式（功能参数）**：
   - `processFeedDeductMode(新料扣减模式)` / `processFeedDeductModeRecycle(回流扣减模式)`：`batch_pick(选手选批)` / `location_fifo(按库位先进先出)` / `either(均可)`。
   - FIFO：不选手选批，必选库位；Either：不选批则 FIFO，选批则按批扣。
   - 库位下拉 +「选择更多」→ 库位选择弹窗（筛名称/类型；列：名称、编码、类型、位置、管理员、可扣量；单选）。
6. **指导量 / 按含量折算**：
   - 配方行开启 `convertByContent(按含量折算)` 时展示指导量 = 剩余理论目标有效量 ÷ 批次有效含量（只读对照，**不截库存**）。
   - 选批或改含量后可预填建议实投；「理论量」列仍展示计划理论量。
   - 选手选批且按含量折算：有效含量必填才能过账；FIFO 允许空含量 → 批次/行记 `contentPending(含量待补)`，事后补录或化验回填。
7. **校验**：至少一行实投 > 0；FIFO 须库位；选批校验剩余量；回流批须通过产出化验硬门禁（若适用）。
8. **本阶段投料记录**：弹窗内可折叠查看；含来源 / 扣减方式 / 批号 / 化验 / 库位 / 实投 / 含量 / 人；待补含量可补录。

## 联副产品与产出

**需求说明**

按配方产出行在对应工序记产出过账（可多行、可中间步产出），不是整张指令结束时一次性入库。

### 角色与处理方式

1. **角色**：主产品 / 联产品 / 副产品 / 回收料 / 废弃物。同一步多条产出分多行过账，不另开指令。
2. **处理方式（执行时选）**：待判定、入仓库、入储罐、**进暂存池**、回用、再提、废弃。
   - **入仓库 / 入储罐**：生成库存批次与生产入库单（`sourceType=批次指令`）；仓管确认入库后批次才可发货或普通投料。
   - **进暂存池**：物料主数据开启「允许车间暂存」才可选；产出落 `await_staging(待暂存合并)`，**不立刻生成**生产入库单；后续在「待处置产出」勾选多行「合并入库」。正式位置：先选仓库或储罐类型，再选该类型下具体位置；换类型清空已选位置。合并条件：同物料 + 有效含量相同（两边都空视为相同；一边空一边有值不相同）；可跨批令、跨暂存位置。合并后批次改待入库，入库单 `sourceType=合并入库`，回写各批令产出行入库单号。功能参数 `workshopStagingMergeContentMode(暂存合并含量策略)` 预留，一期固定「含量须相同」。
   - **回用 / 再提**：生成待回用 / 待再提批次；投料选回流料或开再提指令。
   - **待判定**：先落暂存位置，化验后再确认最终去向。确认入口两处、规则相同：批次指令「产出与追溯」行「确认去向」，以及「待处置产出」列表待判定行的「确认去向」。可选最终去向：回用 / 再提 / 入仓库 / 入储罐 / 进暂存池（物料开关）/ 废弃（**不再含「待判定」**）。硬门禁未合格且非让步时，「确认去向」不可点。
   - **废弃**：拒收，不生成入库单。
3. **角色默认去向（草稿）**：回收料 → 回用；废弃物 → 废弃；联/副产品 → 待判定；主产品默认入仓库或入储罐（可按品名启发入罐），主产品处理方式选项不含「待判定」（须直接选仓/罐/暂存等）。
4. **待处置产出列表**：汇总 `await_decide` / `await_staging` / `await_reuse` / `await_reextract`；筛状态、批次指令、产出批次、物料、处理方式、位置；待判定 → 确认去向；待再提 → 开再提指令；仅车间暂存行可勾选并「合并入库 (N)」。

### 产出登记弹窗（当前）

1. **宽度**：随视口动态 `min(1600, max(1320, 0.92×视口宽))`。
2. **基本信息**：阶段（必选）、补加（带出其他阶段或未指定阶段产出）；**当前异常偏差**（只读最新）；**补充异常偏差**（可选，打开默认空；规则见「批次指令 · 异常偏差」）。
3. **本次登记列**：本次、角色、物料名称、编码、规格型号（物料信息拆列）、预期、已产、本次实产、有效含量(%)、处理方式、去向位置、产出化验。
4. **「本次」勾选**：默认全勾；表头可全选；取消后置灰跳过；仅提交 `included≠false` 且实产 > 0 的行。
5. **去向位置**：生成批次的去向须选位置；入罐限储罐、入仓限仓库/料仓；进暂存 / 待判定 / 回用 / 再提 / 废弃等按规则过滤或不限类型。
6. **有效含量**：界面按 % 录入，存储 0～1；可空；空且生成批次 → `contentPending`，可后补录。滞后登记：若已有完成的产出检且配方未强制必检，尽量从检单带出含量，并默认不勾「发起化验」。
7. **产出化验列**：
   - 配方产出行已配化验 → 锁定「配方必检」，不可取消勾选。
   - 未配 → 文案「发起化验」，可勾选/取消；勾选与文案拆开展示，避免窄列截成「发起」。
   - 表头勾选：全选/取消「发起」（不影响配方必检行）。
   - 已勾发起且同物料同角色同阶段已有检单 → 可再勾「强制新建」。
   - 已有完成检单且未勾发起 → 提示「已有完成检单，可不发起」。
   - 勾选发起即按硬门禁处理：登记时不可直接选回用 / 再提 / 入仓 / 入罐 / 进暂存，须先「待判定」，化验合格（或让步）后再确认去向。
8. **下方区块**：本阶段已登记明细（可折叠，含量待补可补录）；本阶段关联产出化验单（可跳转检单）。
9. **提交顺序**：先 `postOutput(产出过账)`（入仓/入罐生成入库单；进暂存不生成；刷新主产实际产出与得率差；有补充偏差则追加流水）→ 再按行创建/关联产出检单（默认同检单不重复新建，除非强制新建）→ toast 汇总。

### 产出化验与可用性（当前）

1. **时序**：先过账再建检单（不是「化验合格后才允许过账」）。
2. **硬门禁用途**：登记时禁止直接选须合格的去向（含进暂存）；确认去向 / 回流投料 / 开再提时须检单完成且非不合格（通过 / 合格 / 让步类）；待判定、废弃不卡。
3. **批令不再做成品放行**：`releaseOutputBatch(成品放行)` 已废弃。批次对外可用性 = **生产入库确认（released）** +（若有硬门禁）化验结论合格/让步。
4. 含量写在产出批次上，不回写产品主数据、不拆含量 SKU。  
   **未落地**：主元素收率、元素去向分桶、期间金属平衡表。

### 产出与追溯 Tab 展示

1. **异常偏差**：最新说明 + 历史入口（同上）。
2. **产出与物料平衡**：序号、产出类型、物料、阶段、理论/实际产出、占比、去向批号、入库单号。
3. **产出与追溯明细**：序号、角色、物料、阶段、批次号、处理方式、去向位置、数量、有效含量（待补录可补）、剩余、处理状态、检单状态、检验方案、类型、门禁、检验结论、化验单号、入库单号、操作（确认去向 / 开再提指令）。
4. 文案约定：入仓库与入储罐均生成生产入库单，须仓管确认后才可发货或普通投料；硬门禁另须化验合格；**批令页不做成品放行按钮**。

## 质量检验（化验）

**需求说明**

来料、过程、成品、出厂检验保留（页面展示名：来料化验 / 过程化验 / 产出化验 / 出厂化验等；内部 bizScope 可仍为「生产过程检」「成品检」等兼容值）。检验按模板上下限填实测值。

1. **过程化验**：挂在工序 / 配方阶段化验方案；批次「化验」清单按方案发起（类型 / 门禁 / 状态 / 发起；取样位置按化验类型选填）。硬门禁方案未合格则不能确认本步；记录型可多次取样、不挡确认。产出检**不在**此清单发起。
2. **产出化验**：挂在配方**产出行**（勾选启用 + 门禁）；在批次「产出登记」按行勾选「发起化验 / 配方必检」后生成检单（业务范围固定「成品检」）。中间步产出同样可配。多次过账默认同检单关联，除非勾「强制新建」。滞后登记可从已完成检单带出含量。
3. **出厂化验**：走发货/出库，不在产出登记勾选。
4. 来料超限可不合格或让步接收；让步接收写实测含量并允许投料。外协回货检同来料规则。
5. 已入库后发现不合格：部分报废或对原批次开返工指令，不回到原槽次补加流程。
6. **上一步中控取样提示（经验增强）**：打开确认本步 / 投料 / 化验等时，只读提示上一步中控状态；**不拦截**。硬卡仍只由本步过程硬门禁控制。
7. **模板**：过程化验须维护化验类型（投料前核对 / 中控取样 / 转序放行）。匹配：业务类型 + 化验类型 + 物料 + 工序（精确类型优先，兼容旧模板）。
8. **与可用性关系**：产出化验硬门禁约束回用投料、开再提、确认去向、以及入仓/入罐/进暂存前的判定；**不再**依赖批令上的「成品放行」动作。发货与普通投料还须生产入库已确认。

## 采购收货

**需求说明**

采购收货单据保留，用于**外购**和**客供**到货。保存后必须产生原料批次，状态默认待检。没有放行或让步接收记录时，不能被投料选中。

1. 按含量结算的原料一车一批，分开堆放。收货必须写实测含量，作为结算和以后投料折算的依据。供应商提供的含量不能直接当成批次含量。
2. 低于合同含量可以让步接收。批次含量用实测值，折价记在收货行，不改库存数量。不合格批次不能投料。
3. 外协收回不走采购收货，走外协收货（见「外协」一节）。采购收货不再用「委外加工」来源顶替外协闭环。
4. 启用效期的物料同时记生产日期和失效日期。

## 库存、调拨与盘点

**需求说明**

入库、出库、库存明细的单据保留。批次补充状态、含量、检测项、位置、生产日期和直接父批次。状态为待检、合格、让步接收、不合格；启用效期的物料再加过期。

1. 投料和原料出库可以使用合格、让步接收的批次。成品发货只能使用合格批次。待检、不合格不能投、不能发。
2. 调拨执行罐间转移，不能超过罐容。混罐领出不恢复更早的来源。
3. 盘点对象改为批次和罐存。保住身份的罐按批次盘，混罐按结存盘，盘盈盘亏只改结存。启用主元素时，结存可折成同一当量，供期间在制使用。不清空产线。
4. 停用下料结算、余料回库、完工按 BOM 件数扣库，以及库存扣减记录。库存移动保留投料消耗、产出入库、入罐、罐间转移、外协发料出库、外协收回入库。

## 返工与再提

**需求说明**

过程中的补加、复检、参数重记都留在原批次指令，不进返工菜单。

1. **返工**：对已入库（生产入库已确认）批次开再加工指令，数量不超过剩余量；完成后记前/后批次。
2. **再提（当前已支持）**：产出处理方式选「再提」或待判定后再定为再提 → 批次状态待再提 → 「开再提指令」（详情或待处置页）；投料扣该批，产出记前后批次关系。与返工菜单分流。
3. **回用**：产出选「回用」→ 待回用批次；投料时选回流料来源。若该产出挂了产出化验硬门禁，回用/再提前须化验完成且未不合格。

## 销售发货

**需求说明**

销售订单和发货单据保留。订单行选择产品并写计价方式，不选择含量，也不手填一个含量品名。下单时通常还不知道这批货会化验成多少。

1. 按档次一口价：订单写死单价。发货只能选达到该产品合格标准的批次。98.6% 和 99.1% 用同一个价，含量只打印在发货和质检单上。
2. 按含量计价：订单写基准含量、基准单价、含量每高或低一档加减多少钱。订单金额先按基准含量估算。发货时选定已放行批次，用该批次实测含量套这条规则算出结算单价。一车有多批时，按每批的重量分别计价，再合计。
3. 结算重量用过磅净重。价格只按批次实测含量或档次计算。让步接收不用于成品。启用效期时，过期批次不能发。
4. 不做随货配件，不做按单生产挂标。成品只有一种袋重时，袋数用发货重量除以袋重。本期不建包装规格，也不做到袋号。

## 批次追溯

**需求说明**

从原料批次能看到它投进了哪些指令、多少量，含每一轮补加；也能看到它是否发给了外协、对应哪张外协单。从产出批次能看到指令、配方版本、步骤、每笔原料和含量、取样轮次、实际产出、得率，以及同指令的联产品、副产品。启用主元素时能看到收率。外协收回批次能打开外协单、发出批次和转化率。

混罐领出的批次只能再展开一层直接来源。回流在收率里单列，追溯不沿回流继续往前展开。返工能从后批次打开前批次。

本期不建立袋号、桶号，也不做从包装单元发起的投诉反查。

## 工艺参数单位

**需求说明**

工艺参数单位与库存、采购、包装用的单位管理分开。温度、时间、转速、压力、流量这些单位不进库存，也不做公斤和升的换算。

1. 基础配置单独维护工艺参数单位。字段有编码、单位符号、类别、备注、启用状态。类别包括温度、时间、转速、压力、流量、酸碱、电气、其他。
2. 预置 ℃、min、h、s、rpm、pH、MPa、kPa、%、m³/h、L/min、A、Hz。允许新增。符号不能重复。
3. 配方工艺阶段的参数单位从启用的工艺参数单位中选择。停用或删除后，新参数不能再选；已经写在配方上的符号保持原样。
4. 单位只作为批记录上的文字，不参与投料数量换算。
