# 入库辅助单位填法

## 业务背景与目标

流程型 MES 主数据已改为「主单位 + 辅助单位（采购/结算角色）」，本仓库不再服务离散双单位（根/米、张/㎡）客户。入库明细去掉「统一单件 / 逐件 / 直接填合计」按件填法，改为按辅助单位角色填数量。

## 核心业务流程

1. **仅主单位**：只填入库数量（库存单位）。
2. **有采购辅助单位（≠主单位）**：填点收数量（采购单位）+ 入库数量（库存单位）；固定换算率可预填入库数量，允许改。
3. **有结算辅助单位**：再填结算数量合计；总价按结算数量 × 成本价。
4. 确认入库：按库存数量入账，一批一码生成一个批次；不再按采购件数展开 SN。

## 关键业务规则

- 判断「要不要点收列」：采购单位 ≠ 库存单位（来自辅助单位采购角色推导），**不再**用旧 `isVariableLength` 开关做业务判断。
- 行上若仍带 `isVariableLength` / `inboundEntryMode` 等旧字段，入库时强制关闭，避免误走按件展开。
- 结算只保留合计填法。

## 数据模型与接口关联

- 主数据：`auxUnits`（采购/结算角色）、扁平兼容字段 `purchaseUnit` / `settleUnit` / `packageContent`。
- 换算：`purchaseUomConvert.resolvePurchaseConvertRate` / `purchaseQtyToStockQty`。
- 入库行：`purchaseQty`（点收）、`qty`（库存入账）、`settleQty`（结算合计）。
