# 路线驱动阶段 · 去掉配方并行 · 批令支线可关

**日期：** 2026-11-27  
**状态：** 已实现  
**范围：** 配方工艺阶段配置、批次指令阶段确认/完工门禁；工艺路线拓扑为结构真源

## 1. 背景与目标

此前配方上另配「并行关系 + 汇合方式（any/all）」，与工艺路线主/支/汇合拓扑重复，操作门槛高。

目标：

1. **以工艺路线为准**表达分叉结构；配方不再维护并行组。
2. **取消 any/all 汇合门禁**（路线画布也无此交互）。
3. 批令执行时，**仅支线阶段**可对本单「关掉」；关掉则不要求确认、不挡完工。

## 2. 配置侧

### 2.1 配方

- 去掉「并行关系」「汇合方式」列及相关文案。
- 保存时不再写入 `parallelGroupId` / `joinMode`（旧值可清空或忽略）。
- 工艺阶段仍由用户维护（或后续由路线带入）；执行快照仍是 `routeSnapshot`。

### 2.2 工艺路线

- 继续用主线 / 支线 / 汇合点描述结构。
- 节点上遗留的 `joinMode` **不再驱动执行**；可不在 UI 暴露，后续可清字段。

## 3. 批令执行

### 3.1 阶段「本次启用」

| 项                 | 约定                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 字段               | 快照步骤上 `enabledOnOrder`（布尔，默认 `true`）；或等价 `skipped=false`                                                   |
| 谁可关             | **仅**对应路线 `pathKind === branch` 的阶段（匹配键：阶段 `processId` ↔ 路线节点 `processId`，同工序多节点按拓扑序一对一） |
| 主线 / 汇合点      | **不可关**                                                                                                                 |
| 未挂路线或匹配不上 | 视为主线语义：**不可关**，串行确认                                                                                         |
| UI                 | 阶段表开关「本次启用」；关掉后灰显、不可点确认本步                                                                         |

### 3.2 确认时序（开启「批次阶段时序确认」时）

1. 只对 **本次启用** 的阶段做「先确认上一步」类校验。
2. **不做** any/all 并行汇合校验。
3. 紧前若已关掉，则继续向前找最近一个仍启用的阶段作为「上一步」。
4. 同批支线之间互不强制先后（两边都启用时可各自确认，只要各自组前主线已满足）。

### 3.3 完工

- `allRouteStepsConfirmed`：仅要求 **本次启用** 的阶段均已确认；已关掉的支线不算「未完成」。

## 4. 明确不做（本期）

- 配方侧再配并行组 / any/all。
- 主线阶段在批令上关闭。
- 用路线 `joinMode` 驱动门禁。
- 改变「产出拉子批（方案 A）」能力（另配方支线仍可用）。
