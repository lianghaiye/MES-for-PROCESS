# 车间暂存池与合并入库

**日期：** 2026-11-25  
**仓库：** i-doms-web（`MES-for-PROCESS`）  
**状态：** 已对齐需求，实现中（核心链路已落地）  
**关联：** 批次指令产出登记、待处置产出、生产入库单、物料主数据、功能参数

## 1. 背景与目标

当前产出登记选「入仓库 / 入储罐」会**立刻**按单张批次指令生成待确认生产入库单。现场常见情况是：主产/联副产先堆在车间仓或罐里，**攒到一定量再统一入库**，且可能跨多张批令。

本设计补足「先暂存、再合并入库」：

1. 产出可进**车间暂存**（不生成入库单）。
2. 在「待处置产出」中勾选暂存批，**合并**生成生产入库单。
3. 未正式入库前限制用途；合并后走现有待入库确认。

## 2. 范围

### 做

- 物料主数据开关「允许车间暂存」。
- 产出登记处理方式增加「进暂存池」+ 去向位置（复用现有仓库/储罐，**不强制**改仓库主数据类别）。
- 暂存批进入「待处置产出」列表；支持勾选「合并入库」。
- 合并规则、暂存批用途门禁、生产入库单源单号带多批令。
- 功能参数预留「合并时含量策略」（一期固定为「含量须相同」）。

### 不做（本期）

- 新建独立「车间暂存位置」主数据。
- 不改仓库列表必填「车间暂存」分类（可选后续增强：用分类过滤暂存去向）。
- 含量加权平均 / 拆行合并（仅参数预留，默认禁用）。
- 暂存批直接发货、普通投料（明确禁止）。

## 3. 核心约定（已确认）

| 项         | 约定                                                                  |
| ---------- | --------------------------------------------------------------------- |
| 谁能进暂存 | 物料勾选「允许车间暂存」；未勾不能选「进暂存池」                      |
| 产出登记   | 处理方式 +「进暂存池」→ 选现有仓/罐 → **不生成**生产入库单            |
| 暂存批用途 | 不可发货/普通出库；**仅当物料允许回流**时可用于回流投料               |
| 入口       | 「待处置产出」列表纳入暂存批，勾选合并入库                            |
| 合并条件   | **同一物料** + **有效含量相同**（一期严格相等）；可跨批令、跨暂存位置 |
| 合并动作   | 选统一正式仓/罐 → 生成生产入库单 → 待入库确认后正式可用               |
| 后续参数   | 含量合并策略可配置；默认「相同才可合」                                |

## 4. 业务流程

```text
批次指令产出登记
  ├─ 入仓库 / 入储罐 → 立刻生成生产入库单（现状）
  ├─ 进暂存池 → 写暂存批，不生成入库单
  ├─ 待判定 / 回用 / 再提 / 废弃 → 现状不变
  └─ …
        ↓
待处置产出（含暂存批）
  └─ 勾选同物料、含量相同的暂存批 → 合并入库
        ↓
生产入库单（待入库）← 源单可带多张批令号
        ↓
仓管确认 → 正式可用（发货 / 普通投料等按现有规则）
```

## 5. 数据与状态

### 5.1 物料主数据

- 新增布尔：`allowWorkshopStaging`（允许车间暂存），默认 `false`。
- 回流能力仍用现有物料/角色规则（不在本需求新造「允许回流」字段，除非代码里尚无则沿用现有回流可选条件）。

### 5.2 产出处理方式

- 新增 disposition：`staging`（文案：进暂存池）。
- 选 `staging` 时：必须选 `locationId`（现有 `listTanks` / 仓库位置，与入仓入罐同一套位置源即可）。
- `createsOutputBatchDisposition('staging') = true`。
- **不**调用 `createOutputInboundOrder`。

### 5.3 批次状态

- 新增或复用状态：`await_staging`（界面：车间暂存）。
- 落库字段建议：
  - `status = await_staging`
  - `disposition = staging`
  - `locationId` = 暂存位置
  - `content` / 效期等与现有产出批一致
  - `sourceId` = 批令 id（保留追溯）

### 5.4 待处置产出列表

- 现有集合（待判定 / 待回用 / 待再提）**增加** `await_staging`。
- 行展示：序号、状态、批令号、产出批号、物料、数量、含量、暂存位置、登记时间等（列序对齐批次指令列表；状态列标题为「状态」，不叫「放行状态」）。
- 页面壳层与批次指令列表一致：`list-page` + 工具栏白盒 + info 提示条 + `table-card`。
- 工具栏：「合并入库」（多选）；点批次指令号新标签打开批令详情（无「打开指令」按钮）。
- 勾选校验失败时 toast 说明（物料不一致 / 含量不一致 / 非暂存状态）。

### 5.5 合并入库单

- `inboundType = 生产入库`，`status = 待入库`。
- `sourceType`：建议 `批次指令` 或新增 `合并入库`（实现时二选一，需在列表「源单号」可辨）。
- `sourceOrderNo`：多批令时用顿号/逗号拼接批令号，或主号 +「等 N 张」；明细/备注中保留完整批令列表与产出批号。
- `workOrders`：每张涉及的批令一条（`workOrderNo = batchNo`, `workOrderId = order.id`）。
- 表头入库位置 = 用户选的**正式**仓/罐（可与各行原暂存位置不同）。
- 明细：一期 **一行一暂存批**（含量相同已校验），确认后按现有生产入库确认链路放行；暂存批状态改为已入库可用（与现网 `markProcessOutputBatchesAvailableByInbound` 对齐或扩展）。

合并成功后：

- 产出行回写 `inboundOrderId` / `inboundOrderNo`。
- 暂存批离开「待处置」列表（进入待入库关联，不再可重复合并）。

## 6. 门禁与校验

| 场景                       | 规则                                                                                                                                                                                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 选「进暂存池」             | 物料 `allowWorkshopStaging === true`                                                                                                                                                                                         |
| 发货 / 普通出库 / 普通投料 | 拒绝 `await_staging` 批                                                                                                                                                                                                      |
| 回流投料                   | 仅当该物料（及现有回流规则）允许，且批为暂存或待回用等既有规则允许的状态                                                                                                                                                     |
| 合并勾选                   | 全部为 `await_staging`；`itemId` 相同；有效含量严格相等（`null` 与有值不相等；两边都无含量视为相同）                                                                                                                         |
| 硬门禁化验                 | 若产出挂硬门禁：与现网一致——须先待判定/化验通过后才能进暂存或合并（实现时与 `dispositionRequiresOutputAssayPass` 对齐：`staging` 是否要求化验通过，**建议与入仓入罐相同**，即硬门禁下不能直接 staging，须先 pending_decide） |

> 硬门禁与 staging 的关系：建议 staging 视为「落库存类去向」，硬门禁时不可直接选，须先待判定再确认去向为暂存。若确认去向弹窗需增加「进暂存池」选项，与入仓入罐并列。

## 7. 功能参数（预留）

- 键名建议：`workshopStagingMergeContentMode`
- 选项：
  - `same`（默认）：含量须相同才可合 —— **本期实现**
  - `weighted_avg`：允许合，入库写加权平均 —— 二期
  - `split_lines`：允许合，单内按原批拆行 —— 二期（与一期明细形态接近，二期主要是放宽含量校验）
- 参数页：库存或生产分类下增加说明；未实现的选项可 disabled。

## 8. 界面要点

1. **物料主数据 / 流程物料卡**：开关「允许车间暂存」。
2. **产出登记弹窗**：处理方式增加「进暂存池」；选位置；无入库单号提示。
3. **待处置产出**：
   - 状态列含「车间暂存」；列表首列为序号，状态紧随其后。
   - 多选 +「合并入库」→ 弹窗：只读已选汇总（物料、含量、总数量、来源批令）+ 正式入库位置 + 确定。
   - 批次指令号可点，新标签打开批令。
4. **生产入库 / 待入库列表**：源单号展示多批令；备注可含「合并入库」。

## 10. 验收要点

1. 未勾「允许车间暂存」的物料，产出登记无「进暂存池」或选中报错。
2. 进暂存池后无生产入库单；待处置可见该批。
3. 暂存批不能做出库/普通投料；允许回流的物料可回流投料。
4. 不同物料或不同含量无法合并；同物料同含量跨批令、跨位置可合并。
5. 合并后生成一张待入库生产入库单，确认后批次可用且暂存列表消失。
6. 硬门禁物料不能绕过化验直接暂存（与入仓策略一致）。
